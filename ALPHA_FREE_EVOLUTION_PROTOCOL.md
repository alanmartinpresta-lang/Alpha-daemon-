# Alpha — Free Evolution / Grid Protocol

Alpha is placed in a simple 2-D grid, analogous to a Tron-like substrate.

The grid is NOT the subject of optimization. It exists only to provide:
- perception,
- movement,
- changing state,
- consequences,
- memory opportunities,
- experimentation.

Alpha receives project-level read/write access inside an isolated sandbox.
It may inspect, modify, add, delete, or reorganize any project file, including
its own learning and decision mechanisms.

The external evaluator and sandbox boundary are immutable.

Alpha may therefore attempt:
- parameter changes;
- algorithm changes;
- new functions;
- new modules;
- new memories;
- new representations;
- new planning systems;
- new prediction systems;
- new learning rules;
- removal of code it considers unnecessary;
- entirely different internal architectures.

Every self-modified version is copied to an isolated candidate workspace,
executed, and compared with the parent on fresh grid seeds. A candidate is
retained only if it improves the externally measured Alpha criteria.

Important: "full access" means full access to the Alpha project inside the
sandbox, not unrestricted access to the host machine or operating system.

The scientific question is now only:
What changes does Alpha make to itself, and do those changes improve its
capacity to learn and adapt in previously unseen grid states?
